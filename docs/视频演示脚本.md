# 视频演示脚本｜我给求职过程做了一张工作台

**形式：** 真实产品录屏＋本人配音，约 3 分 30 秒，16:9 横屏。用一个问题带观众走过「找岗位 → 判断 → 沟通 → 复盘」。讲真实功能和真实界面，不编造使用成果。镜头编号与文件名见 [录屏与剪辑清单](视频录制清单.md)；录音时可只看 [旁白净稿](视频口播稿.md)。

## 0:00–0:22｜开场：我到底进行到哪一步了？

**画面 A：** 三个短镜头：岗位列表、会话列表、工作台统计。屏幕上依次出现「看过了吗？」「聊过了吗？」「简历发了吗？」三个问题。最后停顿半秒。

**旁白：**

> 找工作时，我以为最费时间的是找岗位。后来发现，更难的是记住找过之后发生了什么：这个岗位我看过吗？这个人我聊过吗？简历到底有没有发出去？
>
> 页面越开越多，答案却越来越难找。

## 0:22–0:43｜揭示：把过程接起来

**画面 B：** 从三个问题切到工作台全景。标题只出现一次：「Job Hunting Helper｜让求职进展有迹可循」。

**旁白：**

> 所以我做了一个本地运行的求职工作台。它把找岗位、准备沟通、跟进会话和回看结果，放进同一条流程里。

## 0:43–1:21｜第一步：岗位从哪里来

**画面 C：** 「配置」中展示推荐流、搜索流或组合模式，以及城市、关键词和岗位要求；切到「采集任务」的当前配置、任务进度和已入库岗位列表。镜头停在「岗位来源」列。已有执行记录就用已有结果演示，不必为拍摄重新采集。

**旁白：**

> 先告诉它，我想找什么。可以看 BOSS 推荐流，也可以按城市和关键词搜索；薪资、学历和工作年限，都由我自己设定。
>
> 采集到的岗位会进入同一个列表，来源和筛选结果都留得下来。下次再看到同一个岗位，我不用重新猜自己有没有看过。

## 1:21–1:56｜第二步：找到之后，先判断

**画面 D：** 在岗位列表搜索一条已准备好的示例岗位，打开详情，依次特写岗位要求、评分理由和招呼语草稿。只展示编辑，不点击真实「发送」。

**旁白：**

> 找到岗位不等于马上联系。我会先看岗位要求；需要时，再让 AI 结合简历给出评分和理由，帮我准备一版招呼语。
>
> 这段话可以改，什么时候发，也由我决定。AI 在这里帮我整理信息，不替我做最后的选择。

## 1:56–2:35｜第三步：联系之后发生了什么

**画面 E：** 「监测任务」依次切换「仅沟通」「有交换」「新会话」。展示已读、未读、追问状态；在「有交换」列表中对照「未确认发送」和「已确认发送」。对涉及真实招聘方的信息打码。

**旁白：**

> 联系之后，线索最容易丢。有人还没读，有人读了没回，有些会话已经有交换。
>
> 我把这些状态分开记录，也能看到哪些会话符合追问条件。这里有个我很在意的细节：「有交换」不代表简历已经投递。只有在消息里核实到发送回执，系统才会标记为已确认发送。

## 2:35–3:13｜最后：把这段时间看清楚

**画面 F：** 回到「工作台」，扫过今日与历史执行记录。图表区关闭「生成前重新扫描」，点击「生成图表」；先让鼠标悬停桑基图的路径，再切到折线图，点击两个主题。尽量让鼠标动作与旁白落点同步。

**旁白：**

> 最后，我想知道，这段时间的求职到底走到了哪里。
>
> 桑基图把沟通、追问和简历发送连成路径；折线图把每天的变化摊开。点一条线，换一个主题，就能看到进展停在哪一步。
>
> 这些数字不能替我决定下一步，但能让我少靠印象，多一点把握。

## 3:13–3:30｜收尾

**画面 G：** 工作台全景慢慢拉远，切到片尾卡：「找岗位、跟进、复盘，放在同一处。」下方显示项目名和仓库地址。

**旁白：**

> 现在它支持 BOSS，在我的电脑上运行。这就是 Job Hunting Helper：一张能记住求职过程的工作台。

## 录制原则

- 用真实界面与已有记录演示，不录入或展示 API Key、简历全文、招聘方头像、私人聊天内容；必要时在剪辑时遮挡。
- 不为镜头执行真实发送、追问或删除。采集镜头可用已有任务记录；若要拍实时采集，先检查当日安全额度。
- 配音正常说话即可，停顿留给画面。录完旁白后再微调镜头长度和字幕，不必硬凑上面的秒数。
