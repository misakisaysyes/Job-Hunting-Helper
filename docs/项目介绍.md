# Job Hunting Helper：让求职进展有迹可循

找工作时，我经常会遇到三个问题：这个岗位以前看过吗？招呼发出后，对方读了吗？这一周到底有多少沟通真正走到了简历投递？

Job Hunting Helper 是我为这些问题做的**本地求职工作台**。它把找岗位、筛选、准备沟通、跟进会话和回顾结果放在一处，让每一步都有记录。项目目前支持 BOSS 直聘，在自己电脑上运行。

## 它怎么工作

1. **设定目标。** 选择 BOSS 推荐流、按城市和关键词搜索，或组合使用；设置薪资、学历、工作年限等要求，以及本轮希望找到的岗位数。
2. **收集岗位。** 系统从已登录的 Chrome 读取岗位，将来源、职位描述和筛选结果整理进岗位池。重复岗位会识别出来；任务进度和每轮结果可以随时查看。
3. **判断是否合适。** 按关键词、状态和分数查找岗位。需要时，让 AI 结合简历给出匹配评分与理由，并生成可编辑的招呼语草稿。
4. **跟进沟通。** 分别扫描「仅沟通」「有交换」「新会话」，记录会话的已读状态、追问进度与附件简历发送回执。发送招呼和追问由你在页面上发起；结果不明确时会留下待核查状态。
5. **回看整个过程。** 工作台汇总当天和历史的采集、监测任务。桑基图展示沟通如何流转，折线图展示每天的变化；生成图表前是否重新扫描会话，由你选择。

**一句话理解：** 把散落在岗位列表、聊天窗口和自己记忆里的求职进展，整理成可以搜索、操作和复盘的工作台。

## 适合谁

如果你会持续看较多岗位，想减少重复筛选、记住沟通上下文，或想知道一段时间内的投递和跟进走到了哪一步，这个项目会比较有用。开启「静默后台运行」后，采集和监测可以在 Chrome 的后台工作标签页进行，不切换正在看的页面，也不移动系统鼠标。

## 使用前知道这些

- 项目当前只接入 BOSS 直聘，需要本机已登录 BOSS 的 Chrome，并开启浏览器调试端口。
- 岗位、会话与任务记录保存在本机。AI 评分和文案生成是可选功能；开启后，所需的岗位和简历内容会发送给你配置的模型服务。
- 「有交换」不等于「简历已投递」。系统只在会话消息中核实到相应回执后，才标记附件简历已确认发送。
- 采集、评分、生成草稿和发送消息是不同步骤；查看评分不会自动联系招聘方。

## 开始使用

准备 Python、Node.js 20.19+ 或 22.12+，以及开启调试端口并登录 BOSS 的 Chrome。在项目根目录运行：

```bash
./web/start.sh
```

打开 `http://127.0.0.1:8000`，先到「配置」设置采集条件，再到「采集任务」开始。需要 AI 功能时，再配置模型 API Key 和简历文件。Chrome 启动方式、完整配置和命令行参数见 [README](../README.md)。

想快速了解使用过程，可以看 [视频演示脚本](视频演示脚本.md)；准备自己录制演示，可照着 [录屏与剪辑清单](视频录制清单.md) 操作。
